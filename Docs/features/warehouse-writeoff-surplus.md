# Списання та оприбуткування надлишків (склад)

Розділи `/warehouse/writeoff` та `/warehouse/surplus` — створення документів у Dilovod, локальна історія з дзеркалом з ERP, редагування сьогоднішніх записів і audit log.

## Маршрути та права

| Шлях | Permission | Мін. роль (seed) |
|------|------------|------------------|
| `/warehouse/writeoff` | `page.warehouse.writeoff` | STOREKEEPER |
| `/warehouse/surplus` | `page.warehouse.surplus` | STOREKEEPER |

Операції відправки / PATCH історії: `action.warehouse.operate`. Видалення історії: `action.warehouse.history.delete`.

У меню для «Оприбуткування» до **20.10.2026** показується бейдж `NEW` (`navBadge` у `client/routes.config.tsx`).

## Dilovod: типи документів

Константи: `shared/types/warehouseGoodDocument.ts`.

| Операція | `header.id` (новий док.) | Поля шапки |
|----------|--------------------------|------------|
| Списання | `documents.goodWriteOff` | `docMode` = `1004000000000304`, `accCosts`, `posted`, склад, фірма |
| Оприбуткування | `documents.goodWriteOn` | **немає `docMode`**; обов’язкові `incomeItem`, `accIncomes`, `business`, `taxAccount` |

Payload збирає `buildGoodDocumentPayload` (`server/modules/Warehouse/warehouseGoodDocumentUtils.ts`). Таблична частина — `tpGoods` з `good`, `goodPart`, `qty`, `accGood`.

Для оприбуткування використовуються типові значення з існуючих документів у базі:

- `WAREHOUSE_SURPLUS_INCOME_ITEM` — «Інші доходи»
- `WAREHOUSE_SURPLUS_ACC_INCOMES` — рахунок доходів

Метадані Dilovod: у `documents.goodWriteOn` поля `docMode` немає (на відміну від `goodWriteOff`). Не передавати `docMode` у payload оприбуткування.

## API

Префікс: `/api/warehouse/writeoff` та `/api/warehouse/surplus`.

| Метод | Шлях | Опис |
|-------|------|------|
| POST | `/send` | Створення документа в Dilovod + запис у локальну історію |
| GET | `/history` | Список (пагінація, sync з Dilovod) |
| GET | `/history/:id/details` | Деталі рядків (lazy enrich) |
| PATCH | `/history/:id` | Редагування (Dilovod `saveType: 2` + локальна БД) |
| GET | `/history/:id/audit` | Журнал змін |
| DELETE | `/history/:id` | Видалення (опційно `delMark` у Dilovod) |

Спільна логіка списку/sync: `warehouseGoodDocumentHistoryList.ts`, `WarehouseGoodDocumentHistorySync.ts`.

- Повний список з Dilovod — не частіше **1 раз на день** (ключі `warehouse.writeoff.history.lastFullListSyncDate` / `warehouse.surplus.history.lastFullListSyncDate`).
- Глибина повного sync: `WAREHOUSE_GOOD_DOC_HISTORY_SYNC_DAYS` (7 днів).
- Сортування історії: спочатку дата документа (`writeOffDate` / `surplusDate` desc), потім `createdAt`, потім `id`.
- Sync оприбуткувань **без фільтра `docMode`** (поле відсутнє в `goodWriteOn`).
- Склади для sync/фільтра списку: `warehouseGoodDocumentStorageFilter.ts`.

Скрипт ручного sync: `npm run` / `npx tsx server/scripts/sync-warehouse-good-doc-history.ts`.

## UI

- Списання: `client/pages/Warehouse/WarehouseWriteOff/`.
- Оприбуткування: `WarehouseSurplus/` — перевикористовує панелі пошуку/рядків з `variant="surplus"` (зелена тема, ліміт кількості **999**).
- Історія: `WarehouseGoodDocumentHistoryTab` + `HistoryAccordionItem`.
- Пошук товару: назва, SKU, штрихкод (плейсхолдер з «ШК»).
- Партії в dropdown: `filterWarehouseSelectableBatches` — без `virtual:`, без системних auto-batch і без віртуальних документів (`canSetTpGoodsGoodPart`, `isAutoGeneratedSystemBatch`).
- При додаванні товару партії підвантажуються лише для рядків з `availableBatches === null` (`useWarehouseReturns.ts`).

## Редагування історії

Спільна перевірка: `canEditWarehouseReleaseHistory` (`shared/utils/releaseHistoryAccess.ts`).

- **Користувач:** лише **свої** записи (`createdBy` = поточний user) і лише **сьогодні** (календарний день Europe/Kyiv за `createdAt`).
- **ADMIN:** без обмежень.
- Записи з sync без автора (`createdBy = 0`) звичайний користувач не редагує.

Та сама логіка застосовується до історії комплектації (`ReleaseHistoryTab`).

Повідомлення при відмові: `WAREHOUSE_HISTORY_EDIT_DENIED_MESSAGE`.
