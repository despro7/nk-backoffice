# Рахунки: генератор рахунків, архів і облік часу (лише admin)

Сторінка `/invoices` (пункт меню «Рахунки») і API `/api/invoices/*`. Доступ: роль `admin` і право `settings.admin` (на сервері обидві перевірки, у клієнті `permission: { name: 'admin' }`).

Три таби, активний лежить в URL-hash (`#tab=archive`, `#tab=new`; дашборд без hash):

| Таб | Що робить |
|-----|-----------|
| Дашборд | Облік часу й оплат: картки, 4 діаграми, зведення по місяцях, таблиця періодів |
| Архів рахунків | Реєстр виставлених рахунків, відкриття / завантаження PDF, видалення |
| Новий рахунок | Генерація рахунку й акта |

Кнопка «Реквізити й налаштування» (праворуч від табів) відкриває модалку з реквізитами отримувача, послугою, тарифом, ставкою години, статусами, підписом і списком платників.

## Зберігання (`settings_base`, категорія `invoices`)

Нових таблиць немає.

| Ключ | Вміст |
|------|-------|
| `invoices_settings` | Один JSON: реквізити отримувача, послуга, призначення платежу, тариф за замовчуванням (2,5), округлення до гривні, примітка про ПДВ, умови оплати, `countedStatuses`, історія ставки години `hourlyRates`, мінімальний наступний номер |
| `invoices_payers` | `JsonCollection` пресетів платників (назва, ІПН/ЄДРПОУ, адреса). Нові додаються при створенні рахунку; стартові 4 ФОП із рахунків №097–109 |
| `invoices_archive` | `JsonCollection` рахунків: знімок на момент створення (платник, реквізити отримувача, рядки, період, порції, тариф, сума, внутрішня корекція) |
| `invoices_periods` | `JsonCollection` півмісячних періодів дашборда: години, тариф, курс, корекція, знімок порцій, `invoiceId` |
| `invoices_signature` | Графічний підпис (`data:image/png|jpeg;base64`). Приватний: лише `GET/PUT /api/invoices/signature`, не лежить у `public/` чи `uploads/` |

Номер рахунку = `max(номери в архіві, nextNumberFloor - 1) + 1` (перший 110). PDF не зберігається файлом: збирається на клієнті (`@react-pdf/renderer`, Arial з `/fonts`) із запису архіву, тож старі рахунки не змінюються після правок налаштувань. Підпис клієнт підтягує з адмінського ендпоінта.

## Рахунок і акт

- **Період** за днем створення (`defaultInvoicePeriod`): з 16 числа й далі 1–15 поточного місяця, з 1 по 15 – 16–кінець попереднього. Можна змінити вручну.
- **Порції** (`PortionsService`) рахуються так само, як `/api/orders/sales/report` (звітний день, `processedItems` кешу замовлень, статуси за замовчуванням 1–5). У підсумку показано «Початок звітного дня», з яким пораховано.
- **Сума** = `round(порції × тариф)` (до гривні, як у старих рахунках) плюс довільні рядки. Тариф фіксується на кожен рахунок. Сума прописом українською: `amountInWordsUa`.
- **Внутрішня корекція** (`adjustmentUah` + примітка) зменшує/збільшує основний рядок, але окремим рядком у PDF не друкується; видно в архіві й дашборді.
- **Акт** №N/1 від тієї ж дати; замовник = платник.

## Дашборд

Формули старої таблиці (`shared/utils/invoiceCalc.ts`, `buildDashboard`):

```
сума, грн     = round(порції × тариф) + корекція
сума, $       = сума, грн / курс
оплачені год  = сума, $ / ставка години
вартість, $   = факт. години × ставка години
накопичений   = овердрафт попереднього періоду + факт. години
овердрафт     = накопичений − оплачені год
Δ, $          = сума, $ − вартість, $
```

- **Режими:** «На момент рахунку» (порції зі знімка; період без знімка – живі) і «Живі дані» (порції перераховані за поточним станом замовлень, різниця зі знімком у таблиці). Під порціями в таблиці підпис «зі знімка» / «живі».
- **Курс USD** береться з НБУ на дату рахунку (для періоду без рахунку – на кінець періоду), можна виправити вручну; джерело (`nbu`, `manual`, `imported`) зберігається.
- **Фільтри:** швидкий період, діапазон дат, скинути. Період, що перетинає межу діапазону, враховується повністю, якщо більша частина його днів у діапазоні.
- **Діаграми:** плавні лінії, стовпчики або стовпчики + лінії (там, де кілька метрик). «Оплачено проти вартості годин» і «Продані порції» мають перемикач напівмісяці / місяці, перша ще й грн / $.
- **Історія** зі старої таблиці (24 періоди, листопад 2025 – жовтень 2026) імпортується один раз при першому відкритті (`historySeed.ts`). Курс там виведений із «суми грн» і «оплачених год». У періоді 01–15.10.2026 корекція −2 960 грн (рахунок №108).

## API (усі: `authenticateToken` + `requireRole(admin)` + `settings.admin`)

| Метод | Шлях | Опис |
|-------|------|------|
| GET / PUT | `/settings` | Налаштування |
| GET / PUT | `/signature` | Підпис (`{ dataUrl }`) |
| GET / POST / DELETE | `/payers`, `/payers/:id` | Пресети платників |
| GET | `/preview?periodStart&periodEnd&tariff` | Порції, сума, порції по днях |
| GET / POST / DELETE | `/archive`, `/archive/:id` | Архів, створення, видалення |
| GET | `/dashboard?mode=history\|live` | Дані дашборда |
| PUT | `/periods/:id` | Години, тариф, курс, корекція |
| POST | `/periods/:id/refresh-rate` | Курс НБУ |
| POST | `/import-history` | Повторний імпорт історії (пропускає наявні періоди) |

## Відомі обмеження

- Порції з поточного звіту продажів не збігаються зі старою таблицею (-0,02…-4%): у таблиці були числа на момент виставлення, а замовлення потім змінювалися; точний збіг не відтворюється жодним набором статусів чи початком звітного дня.
- Імпортована історія рахується за цими формулами, тому 01–15.10.2026 (з корекцією) дає інші суми, ніж у таблиці, де сума була брутто.
